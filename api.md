# HTTP service

Start the service with `python manage.py serve` and open `http://127.0.0.1:8000` for the browser client, or `http://127.0.0.1:8000/docs` for the interactive reference generated by FastAPI.

The service keeps sessions in memory and serialises inference, which suits one process on one machine. It does not store images. It has no authentication of its own, so put it behind your gateway.

## Endpoints

<table>
<tr><th>Method and path</th><th>Purpose</th><th>Body</th></tr>
<tr><td><code>GET /health</code></td><td>Liveness of the service itself</td><td>none</td></tr>
<tr><td><code>GET /v1/model</code></td><td>Model name, thresholds, validation metrics</td><td>none</td></tr>
<tr><td><code>POST /v1/liveness/image</code></td><td>One still image, passive model only</td><td>multipart field <code>file</code></td></tr>
<tr><td><code>POST /v1/liveness/video</code></td><td>A short clip, passive model plus pulse and blinking</td><td>multipart field <code>file</code></td></tr>
<tr><td><code>POST /v1/sessions</code></td><td>Open a session, query <code>mode=interactive</code> or <code>mode=passive</code></td><td>none</td></tr>
<tr><td><code>POST /v1/sessions/{id}/frames</code></td><td>Send the next frame, receive the prompt to show</td><td>multipart field <code>file</code></td></tr>
<tr><td><code>POST /v1/sessions/{id}/finish</code></td><td>Close the session early and get the verdict</td><td>none</td></tr>
<tr><td><code>GET /v1/sessions/{id}</code></td><td>Stage and result of a session</td><td>none</td></tr>
<tr><td><code>DELETE /v1/sessions/{id}</code></td><td>Forget a session</td><td>none</td></tr>
</table>

## Which mode to use

<table>
<tr><th>Mode</th><th>Signals used</th><th>Stops</th><th>Use when</th></tr>
<tr><td>Single image</td><td>Passive model</td><td>Prints and screens the model recognises</td><td>Only a still is available. This is the weakest mode.</td></tr>
<tr><td>Passive clip or session</td><td>Passive model, pulse, spontaneous blinking</td><td>The above, plus static photographs</td><td>The user cannot be prompted, or friction must be minimal</td></tr>
<tr><td>Interactive session</td><td>All four signals</td><td>The above, plus recordings and tilted flat media</td><td>Onboarding, recovery, high value actions</td></tr>
</table>

## Interactive session from Python

```python
import cv2
import httpx

base = "http://127.0.0.1:8000"
camera = cv2.VideoCapture(0)

with httpx.Client(base_url=base, timeout=10) as client:
    session = client.post("/v1/sessions", params={"mode": "interactive"}).json()
    while True:
        ok, frame = camera.read()
        if not ok:
            break
        encoded = cv2.imencode(".jpg", frame)[1].tobytes()
        status = client.post(f"/v1/sessions/{session['session_id']}/frames", files={"file": ("frame.jpg", encoded, "image/jpeg")}).json()
        print(status["stage"], status["prompt"], status["guidance"])
        if status["result"] is not None:
            print(status["result"]["decision"], status["result"]["reasons"])
            break
camera.release()
```

Each response to a frame carries what the client should display.

<table>
<tr><th>Field</th><th>Meaning</th></tr>
<tr><td><code>stage</code></td><td><code>positioning</code>, <code>recenter</code>, <code>challenge</code>, <code>hold</code> or <code>done</code></td></tr>
<tr><td><code>prompt</code></td><td>The instruction for the user, for example "Turn your head to your left"</td></tr>
<tr><td><code>guidance</code></td><td>A hint when the capture is not good enough, for example "Move closer"</td></tr>
<tr><td><code>step</code>, <code>steps</code></td><td>Challenges issued so far and in total</td></tr>
<tr><td><code>challenge_progress</code></td><td>Zero to one, how far the requested action has gone</td></tr>
<tr><td><code>time_left_s</code></td><td>Seconds until the current challenge times out</td></tr>
<tr><td><code>result</code></td><td>Empty until the session is done, then the full verdict</td></tr>
</table>

## Checking a clip or an image

```python
import httpx

with httpx.Client(base_url="http://127.0.0.1:8000", timeout=120) as client:
    with open("assets/samples/live_clip.mp4", "rb") as handle:
        verdict = client.post("/v1/liveness/video", files={"file": ("clip.mp4", handle, "video/mp4")}).json()
    print(verdict["decision"], verdict["score"])

    with open("assets/samples/face.jpg", "rb") as handle:
        verdict = client.post("/v1/liveness/image", files={"file": ("face.jpg", handle, "image/jpeg")}).json()
    print(verdict["decision"], verdict["score"])
```

## The verdict

<table>
<tr><th>Field</th><th>Meaning</th></tr>
<tr><td><code>decision</code></td><td><code>live</code>, <code>not_live</code> or <code>inconclusive</code></td></tr>
<tr><td><code>score</code></td><td>Fused confidence from zero to one. Live needs at least the configured <code>fusion.live_threshold</code>.</td></tr>
<tr><td><code>reasons</code></td><td>Machine readable codes, listed below</td></tr>
<tr><td><code>contributions</code></td><td>How much each signal added to the score</td></tr>
<tr><td><code>signals.passive</code></td><td>Aggregated model score, threshold, number of frames, most likely attack class</td></tr>
<tr><td><code>signals.challenges</code></td><td>Each challenge with outcome and response time</td></tr>
<tr><td><code>signals.depth</code></td><td>Whether enough rotation was seen, the residual and the resulting score</td></tr>
<tr><td><code>signals.pulse</code></td><td>Heart rate estimate, signal to noise ratio and the resulting score</td></tr>
<tr><td><code>model</code></td><td>Model name, run and operating threshold, for audit</td></tr>
</table>

### Reason codes

<table>
<tr><th>Code</th><th>Decision</th><th>Meaning</th></tr>
<tr><td><code>all_checks_passed</code></td><td>live</td><td>Every gate passed and the fused score is high enough</td></tr>
<tr><td><code>pulse_detected</code></td><td>live</td><td>Added when a clear heartbeat supported the decision</td></tr>
<tr><td><code>passive_model_rejected</code></td><td>not live</td><td>The texture model scored far below its threshold</td></tr>
<tr><td><code>challenge_failed:&lt;name&gt;:&lt;why&gt;</code></td><td>not live</td><td>A prompt timed out or was answered with the wrong action</td></tr>
<tr><td><code>flat_surface</code></td><td>not live</td><td>The head turned but moved like a flat object</td></tr>
<tr><td><code>integrity:face_lost</code></td><td>not live</td><td>The face left the frame during the interactive stages</td></tr>
<tr><td><code>integrity:track_discontinuity</code></td><td>not live</td><td>The face jumped or changed size between two frames</td></tr>
<tr><td><code>integrity:multiple_faces</code></td><td>not live</td><td>A second face stayed in view</td></tr>
<tr><td><code>low_confidence:&lt;signal&gt;</code></td><td>not live</td><td>No gate failed but the fused score stayed below the bar, the weakest signal is named</td></tr>
<tr><td><code>insufficient_quality:&lt;issue&gt;</code></td><td>inconclusive</td><td>Too few usable frames, with the last capture problem</td></tr>
<tr><td><code>session_timeout</code>, <code>session_incomplete</code></td><td>inconclusive</td><td>The session ended before all prompts were issued or answered</td></tr>
</table>

## Limits and errors

<table>
<tr><th>Status</th><th>When</th></tr>
<tr><td>400</td><td>The upload is empty or cannot be decoded</td></tr>
<tr><td>404</td><td>Unknown or expired session</td></tr>
<tr><td>413</td><td>Upload larger than <code>api.max_upload_mb</code></td></tr>
<tr><td>422</td><td>Missing field or invalid mode</td></tr>
<tr><td>429</td><td>Too many open sessions</td></tr>
</table>

Sessions expire after `api.session_ttl_s` seconds without a frame. Clips are analysed up to `api.max_video_seconds`. Frame timestamps are taken on arrival at the server, client clocks are ignored.

## Running in a container

```
docker compose up
```

The image contains the inference path only: OpenCV, ONNX Runtime, the three bundled networks and the service. It does not contain PyTorch or any training data.
